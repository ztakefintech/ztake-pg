ztake Order Management API

Create orders, capture UTRs, verify against payments, update status, and receive callbacks.

Base URL

http(s)://your-domain (local: http://localhost:3000)

Authentication Options

  • API Key: Authorization: Bearer pk_... — preferred; links to vendor via api key.
  • Vendor JWT: Authorization: Bearer <vendor-jwt> — also supported.
  • Request body: optional vendorCode field (format: AA4563).
🆕 New: Vendor codes now use human-readable format (AA4563, QX4012, etc.) instead of numeric IDs for better usability.

1) Create Order

POST /api/v1/orders

Content-Type: application/json

Request body

{
  "merchantOrderId": "ORD12345",
  "amount": 250.0,
  "currency": "INR",
  "customerName": "John Doe",
  "returnUrl": "https://merchant.com/payment/return",
  "callbackUrl": "https://merchant.com/payment/callback",
  "vendorCode": "AA4563"   // optional (API key/JWT also supported)
}

Response

{
  "status": "success",
  "merchantOrderId": "ORD12345",
  "ztakeOrderId": "ZTKXXXXXX",
  "paymentUrl": "https://your-domain/orders/ZTKXXXXXX",
  "vendorId": 2,
  "vendorCode": "AA4563"
}

Open paymentUrl to show the payer a UTR submission screen.

2) Get Order

GET /api/v1/orders/{ztakeOrderId}

3) Submit UTR

POST /api/v1/orders/{ztakeOrderId}/submit-utr

Body

{ "utr": "214587963214" }

Behavior:

  • Persists UTR on the order.
  • Verifies the UTR against payments for the same vendor.
  • Always syncs the order amount from the payments row (if found).
  • If the payment has payment_status = 'Succeeded', the order is marked Succeeded and a callback is sent.
  • Prevents reuse: once a payment's UTR is checked (checked_status = TRUE), the same UTR cannot succeed again.

Responses

Status Body Description
200 { success:true, verified:false, status:'Pending', code:'PAYMENT_NOT_SUCCEEDED' } UTR found but payment not succeeded yet.
200 { success:true, verified:true, status:'Succeeded', amount: 250.00 } Verified and succeeded; callback sent.
404 { success:false, code:'UTR_NOT_FOUND' } No payment for this vendor/UTR.
409 { success:false, code:'UTR_ALREADY_USED' } UTR already checked once.
409 { success:false, code:'ALREADY_SUCCEEDED' } Order already succeeded.

4) Update Status (sends callback)

POST /api/v1/orders/{ztakeOrderId}/status

Body

{ "status": "SUCCESS|FAILED|PENDING", "utr": "..." }

Maps to DB statuses Succeeded|Failed|Pending and POSTs a callback.

5) Vendor Orders (UI)

Page: /orders (requires login)

Lists orders for the authenticated vendor. Use API key or vendor JWT when creating orders to associate them.

6) Vendor Payouts API

Create payout requests (UPI or Bank) and list your payout history. Requires vendor auth: Authorization: Bearer pk_... | <jwt>.

Create Payout

POST /api/vendor/payouts

Content-Type: application/json

Request body

{
  "amount": 1500.00,
  "currency": "INR",
  "beneficiary_name": "Jane Doe",
  // Option A: Bank transfer
  "beneficiary_account": "1234567890",
  "beneficiary_ifsc": "HDFC0001234",
  // Option B: UPI transfer (use either bank OR UPI)
  // "beneficiary_upi": "jane@upi",
  "reference_id": "PYT13947473",
  "remarks": "Vendor settlement"
}

Response

{
  "success": true,
  "data": {
    "message": "Payout request created",
    "payout": {
      "id": 42,
      "amount": 1500,
      "currency": "INR",
      "beneficiary_name": "Jane Doe",
      "beneficiary_account": "1234567890",
      "beneficiary_ifsc": "HDFC0001234",
      "beneficiary_upi": null,
      "reference_id": "PYT13947473",
      "remarks": "Vendor settlement",
      "status": "created",
      "created_at": "2025-10-08T10:10:00Z"
    }
  }
}

List Payouts

GET /api/vendor/payouts

Query: ?status=created|approved|paid|failed|rejected (optional)

Response

{
  "success": true,
  "data": {
    "payouts": [
      { "id": 42, "amount": 1500.00, "currency": "INR", "status": "created", "reference_id": "PYT13947473", "created_at": "..." },
      { "id": 41, "amount": 990.00, "currency": "INR", "status": "paid", "reference_id": "PYT98765432", "created_at": "..." }
    ]
  }
}

7) Payment APIs

🆕 Updated: All payment APIs now use vendor codes instead of numeric vendor IDs.

GET /api/vendor/payment-details?vendor_code=AA4563

Response

{
  "success": true,
  "data": {
    "vendor_id": 2,
    "vendor_code": "AA4563",
    "business_name": "My Store",
    "upi_id": "mystore@paytm",
    "bank_name": "HDFC Bank",
    "bank_account_number": "1234567890",
    "bank_account_holder": "My Store",
    "bank_ifsc": "HDFC0001234",
    "qr_code": "base64_encoded_qr_image",
    "created_at": "2025-01-01T00:00:00Z"
  }
}

Public Payment Widget

GET /api/public/payment-widget?vendor_code=AA4563&format=json&theme=light&size=medium

Parameters

  • vendor_code (required) - Vendor Code (format: AA4563)
  • format - json, html, or widget
  • theme - light, dark, or auto
  • size - small, medium, or large

Update Payment Status

POST /api/payments/update

Request body

{
  "utr": "690518190930",
  "amount": 100.00,
  "vendor_code": "AA4563",
  "order_id": "ord_12345",
  "payment_status": "Succeeded"
}

Check Payment Status

POST /api/payments/check

Request body

{
  "utr": "690518190930",
  "vendor_code": "AA4563",
  "order_id": "ord_12345"
}

Callback

Sent on success from submit-UTR (after verification) and from the status endpoint.

Payload

{
  "merchantOrderId": "ORD12345",
  "ztakeOrderId": "ZTKXXXXXX",
  "amount": 250.00,
  "utr": "214587963214",
  "status": "SUCCESS",
  "paymentTime": "2025-09-22T15:20:00+05:30"
}

Tip: Use webhook.site as a test callbackUrl.

Migration Guide

⚠️ Breaking Changes: If you're upgrading from the previous version, update your API calls to use vendor_code instead of vendor_id.

Before (Old Format)

{
  "vendor_id": 123,
  "utr": "690518190930",
  "amount": 100.00
}

After (New Format)

{
  "vendor_code": "AA4563",
  "utr": "690518190930",
  "amount": 100.00
}

Payout ID Format

  • Format: PYT + 8 numbers (e.g., PYT13947473, PYT98765432)
  • Examples: PYT12345678, PYT87654321, PYT11223344
  • Auto-generation: If no reference_id is provided, a unique PYT ID is automatically generated
  • Uniqueness: Each payout ID is guaranteed to be unique across the system
