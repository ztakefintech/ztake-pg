ztake Order Management API

Create orders, capture UTRs, verify against payments, update status, and receive callbacks.

Base URL

http(s)://your-domain (local: http://localhost:3000)

Auth Options

  • API Key: Authorization: Bearer pk_... — preferred; links to vendor via api key.
  • Vendor JWT: Authorization: Bearer <vendor-jwt> — also supported.
  • Request body: optional vendorId field.

1) Create Order

Method
POST
Endpoint
/api/v1/orders
Content-Type
application/json

Request body

{
  "merchantOrderId": "ORD12345",
  "amount": 250.0,
  "currency": "INR",
  "customerName": "John Doe",
  "returnUrl": "https://merchant.com/payment/return",
  "callbackUrl": "https://merchant.com/payment/callback",
  "vendorId": 2   // optional (API key/JWT also supported)
}

Response

{
  "status": "success",
  "merchantOrderId": "ORD12345",
  "ztakeOrderId": "ztakeXXXXXX",
  "paymentUrl": "https://your-domain/orders/ztakeXXXXXX",
  "vendorId": 2
}

Open paymentUrl to show the payer a UTR submission screen.

2) Get Order

Method
GET
Endpoint
/api/v1/orders/{ztakeOrderId}

3) Submit UTR

Method
POST
Endpoint
/api/v1/orders/{ztakeOrderId}/submit-utr
Body
{ "utr": "214587963214" }

Behavior:

  • Persists UTR on the order.
  • Verifies the UTR against payments for the same vendor.
  • Always syncs the order amount from the payments row (if found).
  • If the payment has payment_status = 'Succeeded', the order is marked Succeeded and a callback is sent.
  • Prevents reuse: once a payment’s UTR is checked (checked_status = TRUE), the same UTR cannot succeed again.

Responses

StatusBodyDescription
200{ success:true, verified:false, status:'Pending', code:'PAYMENT_NOT_SUCCEEDED' }UTR found but payment not succeeded yet.
200{ success:true, verified:true, status:'Succeeded', amount: 250.00 }Verified and succeeded; callback sent.
404{ success:false, code:'UTR_NOT_FOUND' }No payment for this vendor/UTR.
409{ success:false, code:'UTR_ALREADY_USED' }UTR already checked once.
409{ success:false, code:'ALREADY_SUCCEEDED' }Order already succeeded.

4) Update Status (sends callback)

Method
POST
Endpoint
/api/v1/orders/{ztakeOrderId}/status
Body
{ "status": "SUCCESS|FAILED|PENDING", "utr": "..." }

Maps to DB statuses Succeeded|Failed|Pending and POSTs a callback.

5) Vendor Orders (UI)

Page
/orders (requires login)

Lists orders for the authenticated vendor. Use API key or vendor JWT when creating orders to associate them.

6) Vendor Payouts API

Create payout requests (UPI or Bank) and list your payout history. Requires vendor auth: Authorization: Bearer pk_... | <jwt>.

Create Payout

Method
POST
Endpoint
/api/vendor/payouts
Content-Type
application/json

Request body

{
  "amount": 1500.00,
  "currency": "INR",
  "beneficiary_name": "Jane Doe",
  // Option A: Bank transfer
  "beneficiary_account": "1234567890",
  "beneficiary_ifsc": "HDFC0001234",
  // Option B: UPI transfer (use either bank OR UPI)
  // "beneficiary_upi": "jane@upi",
  "reference_id": "REF-2025-0001",
  "remarks": "Vendor settlement"
}

Response

{
  "success": true,
  "data": {
    "message": "Payout request created",
    "payout": {
      "id": 42,
      "amount": 1500,
      "currency": "INR",
      "beneficiary_name": "Jane Doe",
      "beneficiary_account": "1234567890",
      "beneficiary_ifsc": "HDFC0001234",
      "beneficiary_upi": null,
      "reference_id": "REF-2025-0001",
      "remarks": "Vendor settlement",
      "status": "created",
      "created_at": "2025-10-08T10:10:00Z"
    }
  }
}

List Payouts

Method
GET
Endpoint
/api/vendor/payouts
Query
?status=created|approved|paid|failed|rejected (optional)

Response

{
  "success": true,
  "data": {
    "payouts": [
      { "id": 42, "amount": 1500.00, "currency": "INR", "status": "created", "reference_id": "REF-2025-0001", "created_at": "..." },
      { "id": 41, "amount": 990.00, "currency": "INR", "status": "paid", "reference_id": "REF-2025-0000", "created_at": "..." }
    ]
  }
}

Admin reviews payout requests in the Admin Panel Payouts tab, pays manually to the provided bank/UPI, and updates status to Approved/Paid/Rejected.

Callback

Sent on success from submit-UTR (after verification) and from the status endpoint.

Payload

{
  "merchantOrderId": "ORD12345",
  "ztakeOrderId": "ztakeXXXXXX",
  "amount": 250.00,
  "utr": "214587963214",
  "status": "SUCCESS",
  "paymentTime": "2025-09-22T15:20:00+05:30"
}

Tip: Use webhook.site as a test callbackUrl.

cURL Samples

Create Order

curl -X POST http://localhost:3000/api/v1/orders \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer pk_your_api_key" \
  -d '{
    "merchantOrderId": "ORD12345",
    "amount": 250.0,
    "currency": "INR",
    "customerName": "John Doe",
    "returnUrl": "https://merchant.com/payment/return",
    "callbackUrl": "https://webhook.site/your-uuid"
  }'

Submit UTR

curl -X POST http://localhost:3000/api/v1/orders/ztakeXXXX/submit-utr \
  -H "Content-Type: application/json" \
  -d '{ "utr": "214587963214" }'

Update Status

curl -X POST http://localhost:3000/api/v1/orders/ztakeXXXX/status \
  -H "Content-Type: application/json" \
  -d '{ "status": "SUCCESS", "utr": "214587963214" }'

Create Payout

curl -X POST http://localhost:3000/api/vendor/payouts \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer pk_your_api_key" \
  -d '{
    "amount": 1500,
    "currency": "INR",
    "beneficiary_name": "Jane Doe",
    "beneficiary_account": "1234567890",
    "beneficiary_ifsc": "HDFC0001234",
    "reference_id": "REF-2025-0001",
    "remarks": "Vendor settlement"
  }'

List Payouts

curl -X GET 'http://localhost:3000/api/vendor/payouts?status=created' \
  -H "Authorization: Bearer pk_your_api_key"
